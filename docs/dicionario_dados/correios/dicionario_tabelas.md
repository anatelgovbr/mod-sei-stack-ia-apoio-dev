# Dicionário de Dados do Módulo SEI Correios - v2.7.2

| Tabela | Descrição |
|---|---|
| md_cor_adm_integr_tokens | Representa a credencial de autenticação de uma funcionalidade de integração com a API dos Correios para um contrato específico do órgão, com uma linha para cada combinação entre funcionalidade de integração e contrato. O registro é criado ou passa a integrar o conjunto quando o administrador cadastra a autenticação de uma funcionalidade para um contrato na tela de Mapeamento das Integrações, ou quando o módulo insere automaticamente um registro vazio ao buscar pela primeira vez a integração de uma funcionalidade ainda não configurada para o contrato. Inclui apenas as combinações de funcionalidade e contrato já solicitadas ou cadastradas e exclui combinações nunca utilizadas. Mantém o estado atual da credencial e do token de autenticação por contrato, referente ao contrato vigente no momento da consulta. É produzido a partir do cadastro administrativo na tela de Mapeamento das Integrações e da renovação automática de token pela API REST dos Correios, e é utilizado pelas chamadas do módulo às APIs dos Correios para autenticar as operações realizadas em nome de cada contrato. Não deve ser interpretado como o cadastro geral da funcionalidade de integração nem como histórico de tokens anteriores, pois mantém apenas a credencial vigente. |
| md_cor_adm_integracao | Representa a configuração de uma funcionalidade da API dos Correios integrada ao módulo, com uma linha para cada funcionalidade oficial suportada. O registro é criado quando o módulo é instalado, populando as dez funcionalidades oficiais previstas (Gerar Token, Rastrear Objeto, Consultar CEP, Serviços Postais, Solicitar Etiquetas, Pré Postagem Nacional, Emitir Rótulo, Download Rótulo, Aviso de Recebimento e Cancelar Pré Postagem), ou quando o administrador mapeia manualmente uma dessas funcionalidades ainda não cadastrada na tela de Mapeamento das Integrações. Inclui somente as funcionalidades oficiais previstas pelo módulo e exclui qualquer outra operação da API dos Correios não mapeada. Mantém a configuração atual do endpoint, da credencial padrão e da situação de cada funcionalidade, referente à configuração vigente no momento da consulta. É produzido pela instalação do módulo e pela manutenção administrativa na tela de Mapeamento das Integrações, e é utilizado pelas chamadas do módulo à API REST dos Correios para localizar o endpoint e a credencial de cada operação, servindo de base para as credenciais específicas por contrato. Não deve ser interpretado como o cadastro de credenciais específicas de cada contrato, que fica em registro à parte por funcionalidade e contrato. |
| md_cor_adm_par_ar_infrigen | Representa um motivo de devolução de objeto postal configurável para o processamento de retorno de Aviso de Recebimento (AR), com uma linha para cada motivo cadastrado. O registro é criado quando o administrador do módulo cadastra um novo motivo na tela Parâmetros para Retorno da AR, seção Motivo de Objeto Devolvido. Inclui motivos ativos e inativos vinculados à parametrização de AR do módulo e exclui motivos usados por outras finalidades do SEI. Mantém o estado atual do cadastro, marcando por exclusão lógica os motivos que não podem ser fisicamente removidos por já estarem vinculados a um processamento de retorno de AR. É produzido a partir do cadastro administrativo do módulo e utilizado para classificar, no processamento de retorno de AR, o motivo pelo qual um objeto foi devolvido e para determinar se esse motivo configura infringência contratual sujeita a cobrança dos Correios. Não deve ser interpretado como o registro do próprio evento de devolução, que é mantido em md_cor_retorno_ar_doc. |
| md_cor_adm_parametro_ar | Representa a configuração de parâmetros para retorno de Aviso de Recebimento (AR) e geração de cobrança de AR pendente do módulo, com uma linha única contendo a configuração vigente do módulo. O registro é criado na primeira gravação dos parâmetros pelo administrador na tela Parâmetros para Retorno da AR e nunca é recriado, apenas alterado nas gravações seguintes, pois a tela sempre consulta e atualiza o único registro existente. Inclui os prazos, tipos de documento, tipo de conferência, regra de nível de acesso e modelo de cobrança usados pelo módulo e exclui os motivos de devolução individuais, mantidos em md_cor_adm_par_ar_infrigen. Mantém o estado atual da configuração, substituído a cada gravação, sem histórico de valores anteriores. É produzido pelo cadastro administrativo do módulo e utilizado pelo processamento de retorno de AR e pela geração de documentos de cobrança de AR pendente. Não deve ser interpretado como um histórico de configurações anteriores, já que somente a configuração vigente é mantida. |
| md_cor_ar_cobranca | Representa um documento de cobrança emitido contra os Correios por pendência de retorno de Aviso de Recebimento (AR), com uma linha para cada documento de cobrança gerado para uma solicitação de expedição. O registro é criado quando o usuário aciona a geração de documento de cobrança na tela ARs Pendentes de Retorno para uma ou mais solicitações de expedição com AR não retornado dentro do prazo contratual. Inclui os documentos de cobrança gerados automaticamente pelo módulo e exclui os documentos de cobrança emitidos manualmente fora do fluxo do módulo. Mantém o histórico de todas as cobranças emitidas para cada solicitação de expedição, permitindo identificar a mais recente. É produzido a partir da geração de documento de cobrança no processo de cobrança configurado em md_cor_adm_parametro_ar e utilizado para relacionar cada documento de cobrança gerado à solicitação de expedição correspondente. Não deve ser interpretado como o registro do próprio retorno do AR, mantido em md_cor_retorno_ar_doc. |
| md_cor_contato | Representa o destinatário de uma solicitação de expedição pelos Correios, com uma linha para cada destinatário vinculado a uma solicitação de expedição. O registro é criado ou passa a integrar o conjunto quando o destinatário é definido ou alterado no cadastro da solicitação de expedição. Inclui apenas destinatários de solicitações de expedição pelos Correios e exclui contatos do SEI que não estejam vinculados a uma solicitação de expedição. Mantém uma fotografia dos dados do contato e do endereço referente ao momento da solicitação, passível de nova cópia quando o contato original é alterado antes da expedição efetiva. É produzido a partir dos dados do contato do SEI e utilizado na impressão de envelopes, etiquetas e documentos de expedição e na consulta do destinatário de cada solicitação. Não deve ser interpretado como o cadastro vigente do contato no SEI, pois reflete uma cópia tirada no momento da solicitação. |
| md_cor_contrato | Representa um contrato firmado entre o órgão e os Correios para uso dos serviços postais integrados ao módulo, com uma linha para cada contrato. O registro é criado quando o administrador cadastra um novo contrato na tela Contratos e Serviços Postais. Inclui contratos ativos e inativos cadastrados no módulo e exclui os serviços postais, tipos de objeto e credenciais de integração vinculados, mantidos em tabelas próprias. Mantém o estado atual dos dados cadastrais e da situação do contrato, referente ao contrato vigente no momento da consulta. É produzido a partir do cadastro administrativo, com base em informações fornecidas pelos Correios ao órgão (número do contrato, cartão de postagem) e do processo SEI de contratação, e é utilizado para vincular serviços postais, tipos de objeto e credenciais de integração ao contrato, bem como nas chamadas à API dos Correios. Não deve ser interpretado como o cadastro dos serviços postais do contrato nem como o processo de contratação em si, apenas referenciado por ele. |
| md_cor_diretoria | Representa uma diretoria regional dos Correios usada para classificar contratos do órgão, com uma linha para cada diretoria regional. O registro é criado na instalação do módulo, que insere as diretorias regionais oficiais dos Correios identificadas por unidade federativa. Inclui as diretorias regionais previstas na instalação do módulo e exclui diretorias eventualmente criadas em versão posterior, para as quais não foi localizada tela de administração acessível a partir do controlador do módulo. Mantém o estado atual do código, da sigla e da descrição de cada diretoria, referente ao cadastro vigente. É produzido pela instalação do módulo e utilizado no cadastro do contrato para indicar a diretoria regional responsável pelo atendimento. Não deve ser interpretado como um cadastro de agências ou unidades operacionais dos Correios, apenas das diretorias regionais. |
| md_cor_expedicao_andamento | Representa um evento de rastreamento identificado pela integração dos Correios para uma solicitação de expedição, com uma linha para cada evento de rastreamento retornado para o código de rastreamento da solicitação. O registro é criado ou passa a integrar o conjunto quando a integração automática de rastreamento, executada em agendamento periódico, identifica um evento ainda não registrado para o objeto postal da solicitação. Inclui os eventos de rastreamento retornados pelo Serviço de Rastreamento de Objetos (SRO) dos Correios para solicitações já expedidas e com código de rastreamento atribuído e exclui eventos já registrados anteriormente para a mesma solicitação, filtrados pela integração para evitar duplicidade. Mantém histórico referente a cada consulta realizada à integração de rastreamento dos Correios desde a expedição do objeto. É produzido a partir da resposta da integração automática com o SRO dos Correios e utilizado para compor a linha do tempo de rastreamento exibida ao usuário e para determinar a situação de rastreamento mais recente da solicitação. Não deve ser interpretado como o registro definitivo e atual da situação da solicitação de expedição, apenas como um evento pontual do histórico de rastreamento. |
| md_cor_expedicao_formato | Representa a escolha de formato de expedição de um documento (principal ou anexo) dentro de uma solicitação de expedição pelos Correios, com uma linha para cada documento ou anexo formatado dentro de uma solicitação de expedição. O registro é criado ou passa a integrar o conjunto quando a unidade solicitante define, no cadastro da solicitação de expedição, a forma de expedição e a impressão de cada documento vinculado. Inclui um registro para o documento principal e um registro para cada anexo incluído na solicitação e exclui documentos de solicitações ainda não cadastradas. Mantém estado atual referente ao momento em que a solicitação de expedição foi cadastrada ou alterada pela última vez. É produzido a partir da escolha da unidade solicitante no formulário de cadastro da solicitação de expedição e utilizado para determinar como cada documento será preparado (impresso em preto e branco, impresso colorido ou gravado em mídia) e para gerar os arquivos entregues aos Correios. Não deve ser interpretado como o cadastro da própria solicitação de expedição, apenas como o detalhamento de formato de cada documento que a compõe. |
| md_cor_expedicao_solicitad | Representa uma solicitação de expedição de um documento principal do SEI pelos Correios, com uma linha para cada documento principal cuja expedição física foi solicitada por uma unidade. O registro é criado ou passa a integrar o conjunto quando a unidade solicitante, a partir de um documento assinado de tipo habilitado para expedição, preenche e confirma o formulário de solicitação de expedição pelos Correios. Inclui as solicitações de expedição física de documentos do SEI para destinatários externos e exclui o envio por meio eletrônico (intimação eletrônica) e o envio de ofício-circular, que o módulo não permite expedir pelos Correios. Mantém estado atual referente ao ciclo de vida da solicitação, desde a criação até a expedição, o recebimento do aviso de recebimento (AR) ou a devolução pela unidade expedidora. É produzida a partir do cadastro realizado pela unidade solicitante e atualizada pelas ações da unidade expedidora e pela integração automática de rastreamento, sendo utilizada para gerar a Pré-Lista de Postagem (PLP), acompanhar o rastreamento do objeto, cobrar avisos de recebimento pendentes e bloquear a expedição física quando o destinatário deve ser intimado eletronicamente. Não deve ser interpretada como o cadastro do próprio documento ou processo do SEI, apenas como o pedido de expedição física associado a eles. |
| md_cor_extensao_midia | Representa a extensão de arquivo do SEI habilitada para gravação em mídia pelo módulo de Correios, com uma linha para cada extensão de arquivo habilitada. O registro é criado quando o administrador seleciona, na tela de Extensões para Gravação em Mídia, uma extensão de arquivo já cadastrada no SEI para uso em expedições gravadas em mídia. Inclui somente extensões de arquivo previamente cadastradas no SEI e exclui qualquer extensão de arquivo ainda não cadastrada no core do sistema. Mantém o estado atual da habilitação referente ao momento da última sincronização feita pelo administrador na tela de Extensões para Gravação em Mídia. É produzido a partir da seleção manual do administrador do módulo e utilizado para restringir quais tipos de arquivo podem ser gravados em mídia numa expedição pelos Correios. Não deve ser interpretado como o cadastro da extensão de arquivo em si, que pertence ao core do SEI. |
| md_cor_justificativa | Representa um motivo cadastrado para marcar um contato como destinatário não habilitado para expedição física pelos Correios, com uma linha para cada motivo cadastrado. O registro é criado quando um administrador cadastra um novo motivo na tela de Justificativas de Destinatários não Habilitados para Expedição. Inclui apenas motivos usados para desabilitar a expedição física a um destinatário e exclui motivos de devolução de objetos postados, tratados em tabela própria. Mantém o estado atual do motivo, incluindo se está disponível para seleção. É produzido por cadastro manual do administrador do módulo e utilizado ao vincular um contato como destinatário não habilitado para expedição física. Não deve ser interpretado como o próprio registro de não habilitação de um destinatário, que fica em tabela própria. |
| md_cor_lista_status | Representa o mapeamento entre uma combinação de código e tipo de evento do Serviço de Rastreamento de Objetos (SRO) dos Correios e a classificação de rastreamento usada pelo módulo, com uma linha para cada combinação de código (status) e tipo (tipo) de evento reconhecida pelo módulo. O registro é criado ou passa a integrar o conjunto na instalação do módulo, a partir da carga inicial de combinações conhecidas na época, ou automaticamente quando a integração de rastreamento recebe da API do SRO uma combinação de código e tipo ainda não cadastrada, ou manualmente quando um administrador cadastra ou ajusta uma combinação pela tela de parametrização de status. Inclui as combinações de código e tipo de evento já observadas nas respostas do SRO e exclui eventos de rastreamento que não estejam associados a nenhuma combinação cadastrada, que permanecem sem classificação de rastreio do módulo até serem parametrizados. Mantém estado atual referente à classificação vigente de cada combinação código/tipo. É produzido a partir da carga inicial do módulo, da parametrização manual por administradores e do cadastro automático de combinações desconhecidas pela integração de rastreamento, sendo utilizado para classificar os eventos de md_cor_expedicao_andamento em uma situação de rastreio do módulo (Postado, Em trânsito, Sucesso na entrega, Insucesso na entrega ou ainda não classificado) e para decidir se um evento é exibido no rastreamento. Não deve ser interpretado como o histórico de eventos de uma solicitação específica, apenas como o catálogo de classificação usado para interpretar esses eventos. |
| md_cor_map_unid_servico | Associa unidade solicitante a serviço postal, com uma linha para cada combinação de unidade solicitante e serviço postal habilitada. O registro é criado ou passa a integrar o conjunto quando o administrador do módulo inclui um serviço postal na lista de serviços disponíveis para uma unidade solicitante. Inclui apenas combinações entre unidades do SEI e serviços postais cadastrados nos contratos com os Correios e exclui serviços ainda não habilitados para a unidade. Mantém o estado atual do vínculo entre a unidade e o serviço postal. É produzido por cadastro manual do administrador do módulo e utilizado para restringir quais serviços postais uma unidade solicitante pode escolher ao solicitar expedição. Não deve ser interpretado como o mapeamento entre unidade expedidora e unidade solicitante, tratado em tabela própria. |
| md_cor_map_unidade_exp | Associa unidade expedidora a unidade solicitante, com uma linha para cada combinação de unidade expedidora e unidade solicitante autorizada. O registro é criado ou passa a integrar o conjunto quando o administrador do módulo inclui a unidade solicitante no mapeamento de uma unidade expedidora. Inclui apenas combinações de unidades do SEI habilitadas a solicitar expedição física para uma unidade expedidora específica e exclui unidades ainda não mapeadas. Mantém o estado atual do vínculo entre as duas unidades. É produzido por cadastro manual do administrador do módulo e utilizado para restringir quais unidades solicitantes podem enviar solicitações de expedição para cada unidade expedidora. Não deve ser interpretado como o mapeamento entre unidade solicitante e serviço postal, tratado em tabela própria. |
| md_cor_objeto | Representa a configuração de embalagem, rótulo e margens de impressão utilizada nas expedições de um contrato dos Correios, com uma linha para cada combinação de tipo de embalagem e contrato configurada pelo administrador. O registro é criado quando o administrador cadastra, na tela de Tipos de Embalagem do contrato, uma nova configuração de objeto postal para um tipo de embalagem existente. Inclui apenas configurações vinculadas a um contrato e a um tipo de embalagem previamente cadastrados e exclui tipos de embalagem sem nenhuma configuração de margem e rótulo definida. Mantém o estado atual da configuração referente ao momento do último cadastro ou alteração feita pelo administrador, podendo ser marcada como inativa quando sua exclusão é solicitada mas ela já está vinculada a solicitações de expedição. É produzido a partir do cadastro manual do administrador do módulo e utilizado para determinar o rótulo e as margens de impressão aplicados à etiqueta de expedição de um objeto postal. Não deve ser interpretado como o tipo de embalagem em si, que é mantido separadamente em md_cor_tipo_objeto. |
| md_cor_plp | Representa uma Pré-Lista de Postagem (PLP) gerada pelo módulo para um conjunto de solicitações de expedição, com uma linha para cada PLP gerada por uma unidade expedidora. O registro é criado ou passa a integrar o conjunto quando a unidade expedidora seleciona uma ou mais solicitações de expedição pendentes de atendimento e aciona a geração de PLP, momento em que o módulo obtém da integração com os Correios os códigos de rastreamento e o identificador de pré-postagem de cada solicitação incluída. Inclui as PLPs geradas a partir de solicitações de expedição pendentes de uma ou mais unidades solicitantes mapeadas para a unidade expedidora e exclui solicitações que ainda não foram agrupadas em uma PLP. Mantém estado atual referente à situação corrente da PLP ao longo de seu ciclo de expedição, do processamento de retorno de AR e, quando aplicável, do cancelamento. É produzida a partir da ação de geração de PLP executada pela unidade expedidora e utilizada para agrupar a impressão de documentos, envelopes, ARs e vouchers, para controlar a expedição física conjunta das solicitações agrupadas e para acompanhar pendências de retorno de AR. Não deve ser interpretada como o cadastro individual de cada solicitação de expedição, apenas como o agrupamento operacional dessas solicitações para expedição. |
| md_cor_retorno_ar | Representa um lote de processamento de retorno de Aviso de Recebimento (AR) dos Correios, com uma linha para cada arquivo ZIP de imagens de AR submetido ao processamento. O registro é criado quando um usuário da unidade expedidora submete um arquivo ZIP contendo até 50 arquivos PDF de AR na tela Processamento de Retorno de AR. Inclui os lotes submetidos para processamento automático ou manual e exclui os arquivos individuais de cada AR, mantidos em md_cor_retorno_ar_doc. Mantém o estado atual do lote quanto à autenticação digital, atualizado quando o lote é assinado. É produzido pelo upload do arquivo ZIP na tela Processamento de Retorno de AR e utilizado para agrupar e posteriormente autenticar os documentos de AR reconhecidos ou informados manualmente no lote. Não deve ser interpretado como o resultado do processamento de cada AR individual, mantido em md_cor_retorno_ar_doc. |
| md_cor_retorno_ar_doc | Representa o processamento de um arquivo PDF de Aviso de Recebimento (AR) individual dentro de um lote de retorno, com uma linha para cada arquivo PDF de AR processado. O registro é criado quando o módulo processa um arquivo PDF extraído do lote de retorno de AR, seja pela leitura automática do código de barras QR Code impresso pelo próprio módulo, seja pela indicação manual do número do processo SEI pelo usuário. Inclui os ARs identificados automaticamente, indicados manualmente e não identificados e exclui os arquivos ainda não processados, mantidos apenas no lote em md_cor_retorno_ar. Mantém o estado atual do processamento de cada AR, podendo ser alterado posteriormente pelo usuário. É produzido a partir da leitura de imagem do arquivo PDF e das informações preenchidas na tela de processamento e utilizado para registrar a data de recebimento e retorno do AR, vincular o AR ao documento principal e ao processo correspondente e determinar o motivo quando o objeto é devolvido. Não deve ser interpretado como o próprio arquivo PDF do AR, apenas como o registro de seu processamento. |
| md_cor_serie_exp | Representa o tipo de documento do SEI habilitado para solicitação de expedição pelos Correios, com uma linha para cada tipo de documento habilitado. O registro é criado quando o administrador seleciona, na tela de Tipos de Documentos de Expedição, um tipo de documento do SEI que já possui indicação de preenchimento de destinatário. Inclui somente tipos de documento do SEI com indicação de destinatário habilitada em sua configuração e exclui tipos de documento sem essa indicação. Mantém o estado atual da seleção referente ao momento da última sincronização feita pelo administrador na tela de Tipos de Documentos de Expedição, já que a remoção de um tipo da seleção exclui fisicamente o registro em vez de desativá-lo. É produzido a partir da seleção manual do administrador do módulo e utilizado para determinar em quais tipos de documento assinados é exibido o botão de solicitação de expedição pelos Correios. Não deve ser interpretado como o cadastro do tipo de documento em si, mantido pelo core do SEI na tabela serie. |
| md_cor_servico_postal | Representa um serviço postal dos Correios disponibilizado para uso em um contrato do órgão, com uma linha para cada serviço postal configurado por contrato. O registro é criado quando o administrador busca, na tela de Contratos e Serviços Postais, os serviços postais disponíveis para o contrato junto à API dos Correios e configura manualmente o tipo de correspondência, o aviso de recebimento, a cobrança e a permissão de anexar mídia de cada serviço retornado. Inclui os serviços postais retornados pela integração com os Correios para o contrato e mantidos pelo administrador, e exclui serviços postais não vinculados a nenhum contrato cadastrado no módulo. Mantém o estado atual da configuração referente ao momento da última busca ou alteração feita pelo administrador. É produzido a partir da integração com a API de serviços postais dos Correios combinada com a configuração manual do administrador e utilizado para disponibilizar o serviço postal na solicitação de expedição de documentos. Não deve ser interpretado como o contrato em si, mantido separadamente em md_cor_contrato. |
| md_cor_status_process | Representa um resultado possível do processamento automatizado de um arquivo de retorno de AR, com uma linha para cada resultado de processamento previsto pelo módulo. O registro é criado exclusivamente pelo script de instalação do módulo, que popula o conjunto fechado de resultados possíveis; nenhuma ação do controlador do módulo permite cadastrar, alterar ou excluir esses registros pela interface. Inclui exclusivamente os quatro resultados de processamento previstos pelo módulo e exclui os motivos complementares de não processamento, mantidos em md_cor_substatus_process. Mantém o estado fixo definido na instalação do módulo, sem histórico de alteração. É produzido pelo script de instalação do módulo e utilizado para classificar, em md_cor_retorno_ar_doc, o resultado do processamento automatizado de cada arquivo de AR. Não deve ser interpretado como o motivo complementar de um resultado não processado, mantido em md_cor_substatus_process. |
| md_cor_substatus_process | Representa um motivo complementar para o resultado Não Processado do processamento automatizado de retorno de AR, com uma linha para cada motivo complementar previsto pelo módulo. O registro é criado exclusivamente pelo script de instalação do módulo, que popula o conjunto fechado de motivos complementares possíveis; nenhuma ação do controlador do módulo permite cadastrar, alterar ou excluir esses registros pela interface. Inclui exclusivamente os motivos complementares vinculados ao resultado Não Processado e exclui os demais resultados de processamento, mantidos em md_cor_status_process. Mantém o estado fixo definido na instalação do módulo, sem histórico de alteração. É produzido pelo script de instalação do módulo e utilizado para detalhar, em md_cor_retorno_ar_doc, por que um arquivo de AR não foi processado automaticamente. Não deve ser interpretado como um resultado de processamento autônomo, já que sempre complementa o resultado Não Processado de md_cor_status_process. |
| md_cor_tipo_correspondenc | Representa um tipo de correspondência utilizado para classificar os serviços postais disponíveis no módulo de Correios, com uma linha para cada tipo de correspondência cadastrado. O registro é criado na instalação do módulo, que popula sete tipos padrão dos Correios (Carta Simples, Carta Registrada, SEDEX Hoje, SEDEX 10, SEDEX 12, SEDEX e PAC); a regra de negócio do módulo mantém métodos internos de inclusão, alteração e exclusão, para os quais não foi localizado recurso de permissão nem tela de administração acessível a partir do controlador do módulo. Inclui os tipos de correspondência utilizados para vincular serviços postais no cadastro do contrato e exclui os próprios serviços postais, mantidos em md_cor_servico_postal. Mantém o estado fixo definido na instalação do módulo, sem histórico de alteração administrativa observável. É produzido pela instalação do módulo e utilizado para determinar se o serviço postal admite Aviso de Recebimento e qual chancela é aplicada na expedição. Não deve ser interpretado como o serviço postal em si, mantido separadamente em md_cor_servico_postal. |
| md_cor_tipo_objeto | Representa um tipo de embalagem postal disponível para configuração de objetos de expedição, com uma linha para cada tipo de embalagem cadastrado. O registro é criado na instalação do módulo, que popula os tipos padrão Envelope, Caixa e Cilindro; a regra de negócio do módulo mantém métodos internos de inclusão, alteração e exclusão, para os quais não foi localizado recurso de permissão nem tela de administração acessível a partir do controlador do módulo. Inclui os tipos de embalagem utilizados para configurar objetos postais e exclui as próprias configurações de objeto, mantidas em md_cor_objeto. Mantém o estado fixo definido na instalação do módulo, sem histórico de alteração administrativa observável. É produzido pela instalação do módulo e utilizado para classificar a configuração de margens e rótulo de impressão de um objeto postal. Não deve ser interpretado como a configuração de margens e rótulo em si, mantida separadamente em md_cor_objeto. |
| md_cor_unidade_exp | Representa uma unidade do SEI habilitada a expedir fisicamente correspondências pelos Correios, com uma linha para cada unidade habilitada como expedidora. O registro é criado quando o administrador do módulo cadastra a unidade na tela de Unidades Expedidoras. Inclui apenas unidades do SEI autorizadas a realizar a validação e a efetivação da expedição física e exclui as demais unidades do órgão. Mantém o estado atual da habilitação da unidade como expedidora. É produzido por cadastro manual do administrador do módulo, a partir de uma unidade do SEI, e utilizado para restringir quais unidades podem processar PLPs (Pré-Listas de Postagem) e efetivar a expedição física de correspondências. Não deve ser interpretado como o mapeamento entre unidade expedidora e unidade solicitante, tratado em tabela própria. |
| rel_contato_justificativa | Representa a marcação de um contato do SEI como destinatário não habilitado para expedição física pelos Correios, com uma linha para cada contato marcado como não habilitado. Inclui contatos impedidos de receber correspondência física por já disporem de meio eletrônico de comunicação e exclui contatos sem essa restrição. Mantém o estado atual da marcação de não habilitação referente ao contato. É produzido por cadastro manual do administrador do módulo, a partir de um contato do SEI e de um motivo cadastrado, e utilizado para bloquear e alertar sobre a solicitação de expedição física de correspondência a esses contatos. Não deve ser interpretado como o próprio motivo de não habilitação, que fica na tabela de justificativas. |
